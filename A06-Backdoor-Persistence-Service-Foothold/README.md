# Backdoor / Persistence / Service Foothold Class

|ID|Technique|Core Transition|Dominant APIs / Mechanisms|Static Artifacts (Ghidra)|Dynamic Artifacts (Procmon / PCAP / Sysmon)|Semantic Meaning|
|---|---|---|---|---|---|---|
|**A06_1a**|Registry Run-Key Persistence|installer → HKCU Run value → user logon autostart → marker execution|`RegOpenKeyExW`, `RegCreateKeyExW`, `RegQueryValueExW`, `RegSetValueExW`, `CreateFileA`, `WriteFile`, `OutputDebugStringA`|HKCU Run key path, MachineGuid registry path, normalized value-name logic, hardcoded marker path, `REG_SZ` autostart value|Run-key value creation, marker execution after logon/reboot, marker file in `C:\Users\Public`, debug string emission|Demonstrates classic user-level autostart persistence through a Run-key value that launches a benign marker during user logon|
|**A06_1b**|Offline Registry Hive Save/Restore Persistence|offline NTUSER.DAT → Run-key insertion → hive replacement → target-user logon autostart|`OROpenHive`, `ORCreateKey`, `ORSetValue`, `ORSaveHive`, `ORCloseKey`, `File.Copy`, `File.Delete`|`offreg.dll` usage, staged and target `NTUSER.DAT` paths, Run-key path, hardcoded persistence value, marker payload path|Offline hive access, target hive overwrite, restored Run-key value after profile load, marker execution after target-user logon|Shows indirect Run-key persistence by modifying an offline user hive instead of writing directly to the live registry|
|**A06_2**|Windows Service Persistence Watchdog|manual execution → auto-start service install → service session bridge → user-session watchdog → payload loop|`OpenSCManager`, `CreateService`, `StartServiceCtrlDispatcher`, `RegisterServiceCtrlHandlerEx`, `WTSQueryUserToken`, `DuplicateTokenEx`, `CreateProcessAsUserW`, `SetTimer`|Service name, auto-start configuration, WTS/session APIs, token impersonation logic, watchdog timer, payload path registry value|Service creation, service logs, launcher process in user session, recurring payload execution, sample log growth|Demonstrates durable service-based persistence that bridges from Session 0 into an interactive user session and maintains a benign payload|
|**A06_3a**|COM Logon Scheduled Task Persistence|installer → Task Scheduler COM registration → user logon trigger → SYSTEM marker execution|`CoInitializeEx`, `CoInitializeSecurity`, `ITaskService::Connect`, `ITriggerCollection::Create`, `ILogonTrigger`, `IExecAction::put_Path`, `RegisterTaskDefinition`|Task Scheduler COM usage, `TASK_TRIGGER_LOGON`, `TASK_LOGON_SERVICE_ACCOUNT`, hardcoded task name, payload path|Scheduled task registration, task launch at logon, marker process execution, recurring log entries|Uses Task Scheduler COM APIs to establish SYSTEM-context logon-triggered persistence|
|**A06_3b**|COM Event-Triggered Scheduled Task Persistence|installer → event-triggered task → Security Event ID 4688 match → marker execution|`.NET COM interop`, `Schedule.Service`, `EventTrigger.Subscription`, XML event filter, `RegisterTaskDefinition`|COM interop strings, XML event subscription, Security Event ID `4688`, `firefox.exe` process filter, payload path|Task creation, Firefox launch event, Task Scheduler trigger activation, marker log file creation|Demonstrates conditional event-driven persistence that activates only when a specific process-creation event occurs|
|**A06_3c**|COM Recurring Scheduled Task Persistence|installer → time-triggered task → recurring 1-minute execution → repeated marker logs|`CoCreateInstance`, `ITaskService`, `ITimeTrigger`, `IRepetitionPattern::put_Interval`, `IExecAction`, `RegisterTaskDefinition`|`TASK_TRIGGER_TIME`, ISO start-boundary logic, `PT1M` repetition interval, SYSTEM logon type, task name and payload path|Recurring scheduled executions, repeated payload launches/log entries, Task Scheduler Operational events|Models time-based persistence where execution is decoupled from user activity and occurs at fixed recurring intervals|
|**A06_3d**|`schtasks.exe` On-Logon Scheduled Task Persistence|installer → `schtasks.exe /create` → logon trigger → SYSTEM marker execution|`CreateProcessW`, `WaitForSingleObject`, `GetExitCodeProcess`, `schtasks.exe`, `ONLOGON` trigger|Hardcoded `schtasks.exe` command line, task name, `/sc onlogon`, `/ru SYSTEM`, payload path|Installer spawns `schtasks.exe`, task file creation, marker execution after logon, recurring marker log growth|Demonstrates command-line scheduled-task persistence using `schtasks.exe` instead of direct COM registration|
|**A06_4**|WMI Event Subscription Persistence|installer → permanent WMI filter/consumer/binding → registry value change → marker execution|`ManagementScope`, `__EventFilter`, `CommandLineEventConsumer`, `__FilterToConsumerBinding`, `RegistryKey.SetValue`, `CreateFileA`, `OutputDebugStringA`|`root\subscription`, WQL `RegistryValueChangeEvent`, filter/consumer names, registry trigger path, marker executable path|WMI objects created, registry trigger modification, WMI-launched marker process, marker file artifact|Demonstrates event-driven WMI persistence using a permanent subscription that launches a payload when a registry value changes|
|**A06_5**|System Startup Folder + RDP Foothold|manual execution → self-copy to All Users Startup → startup execution → account/RDP/firewall configuration|`GetModuleFileNameW`, `SHGetFolderPathW`, `CopyFileW`, `NetUserAdd`, `NetLocalGroupAddMembers`, `RegSetValueExW`, `INetFwPolicy2::EnableRuleGroup`|Startup folder path, self-copy filename, hardcoded local account, RDP registry paths, Winlogon `SpecialAccounts`, firewall COM usage|Startup-folder copy, local account creation, Administrators membership change, RDP enabled, NLA disabled, firewall rule group enabled|Combines autostart persistence with controlled RDP foothold configuration to model backdoor-style remote access setup|
|**A06_6**|DNS Backdoor with Command Polling|agent → DNS TXT command retrieval → benign command execution → DNS query exfiltration loop|`DnsQuery_W`, `DnsRecordListFree`, `Marshal` pointer parsing, `Convert.FromBase64String`, `Process.Start`, `StandardOutput.ReadToEnd`, `Thread.Sleep`|`dnsapi.dll` P/Invoke, hardcoded `agent77.cmd.lab.local`, TXT record parsing, Base64 decode/encode logic, `cmd.exe /c ping`, `data.<index>.<chunk>` domain pattern|Periodic DNS TXT lookups, `cmd.exe` child process, DNS A-record exfiltration queries, Base64 chunks in DNS labels, no persistence artifacts|Demonstrates DNS-based C2 where commands arrive through TXT records and command output leaves through DNS query labels|
