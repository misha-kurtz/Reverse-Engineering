
## A04 Spyware / Cred Theft / Keylogger / Exfil Class 

|ID|Technique|Core Transition|Dominant APIs / Mechanisms|Static Artifacts (Ghidra)|Dynamic Artifacts (Procmon / PCAP / Sysmon)|Semantic Meaning|
|---|---|---|---|---|---|---|
|**A04_1a**|Hook-Based Keystroke Logging|user input → keyboard hook callback → captured keystrokes → local log|`.NET SetWindowsHookEx`, `CallNextHookEx`, `UnhookWindowsHookEx`, `GetModuleHandle`, keyboard-event callback logic, file I/O|Keyboard-hook imports, low-level keyboard callback, virtual-key translation logic, keystroke buffer, log-file paths and strings|Long-running process, hook-triggered execution following keyboard input, repeated writes to the keystroke log, little or no network activity|Captures user keystrokes through an event-driven Windows keyboard hook and records them for later collection|
|**A04_1b**|Polling-Based Keystroke Logging|keyboard state → repeated key polling → translated characters → local log|`GetAsyncKeyState`, `GetKeyState`, `MapVirtualKey`, `GetKeyboardState`, `ToUnicode`, `Sleep`, file I/O|Large virtual-key polling loop, keyboard-state checks, key translation routines, timing delay, output-file path|Frequent keyboard-state queries, recurring short sleep intervals, repeated append operations to the log file, sustained execution without outbound traffic|Captures keystrokes by continuously polling keyboard state rather than registering an event-driven hook|
|**A04_2**|Windows Credential Manager Extraction|target user session → privileged token impersonation → Credential Manager backup → DPAPI decryption → parsed credentials|`OpenProcessToken`, `LookupPrivilegeValue`, `AdjustTokenPrivileges`, `DuplicateTokenEx`, `ImpersonateLoggedOnUser`, `CredBackupCredentials`, `ProtectedData.Unprotect`, `RevertToSelf`|Privilege strings such as `SeDebugPrivilege` and `SeTrustedCredManAccessPrivilege`, `winlogon.exe` references, token-duplication logic, Credential Manager backup structures, DPAPI decryption routines, temporary backup path|Process and token access involving `winlogon.exe`, privilege adjustments, creation and deletion of a temporary credential backup, impersonation activity, no required outbound network traffic|Uses a privileged impersonation context to back up and decrypt Windows Credential Manager data associated with a selected user session|
|**A04_3**|System and Host Reconnaissance|local host state → system-command enumeration → consolidated reconnaissance report|`GetUserNameA`, `GetSystemInfo`, `ShowWindow`, `system`, built-in utilities including `ipconfig`, `getmac`, `nslookup`, `route`, `net user`, `net localgroup`, `netstat`, `tasklist`, `reg query`, and `wmic qfe`|Hardcoded reconnaissance commands, `C:\Users\Public\A04_3_System_Host_Recon_OK.txt`, system-information structures, command-redirection strings, labeled report sections|Creation and repeated append operations to the reconnaissance log, child processes such as `ipconfig.exe`, `net.exe`, `netstat.exe`, `tasklist.exe`, `reg.exe`, `wmic.exe`, and `nslookup.exe`; DNS traffic for the public-IP query|Profiles the local host, users, software, processes, network configuration, sockets, routes, and patch state without directly exfiltrating the collected report|
|**A04_4a**|HTTP JSON Data Exfiltration|host identity → JSON serialization → HTTP POST → controlled collection endpoint|`GetUserNameA`, `GetComputerNameA`, `InternetOpenA`, `InternetConnectA`, `HttpOpenRequestA`, `HttpSendRequestA`, `CreateThread`, `Sleep`, manual JSON formatting|`c2.lab.local`, `/api/v1/report`, `DataPipelineAgent/1.0`, `application/json`, JSON field names, `location_heartbeat`, WinINet imports, one-hour sleep constant|DNS query for `c2.lab.local`, TCP connection to port 80, cleartext HTTP POST requests, visible JSON request body, initial transmission followed by periodic heartbeat traffic|Serializes collected host identity information as JSON and transmits it directly over unencrypted HTTP|
|**A04_4b**|HTTP Form-Encoded Data Exfiltration|host identity → form-encoded key-value serialization → HTTP POST → controlled collection endpoint|`GetUserNameA`, `GetComputerNameA`, `InternetOpenA`, `InternetConnectA`, `HttpOpenRequestA`, `HttpSendRequestA`, `CreateThread`, `Sleep`, `sprintf_s`|`application/x-www-form-urlencoded`, `username=`, `computer_name=`, `login_time=`, `status=location_heartbeat`, `DataPipelineAgent/1.1`, C2 hostname and request path|DNS query followed by TCP port 80 traffic, HTTP POST requests containing ampersand-separated key-value pairs, visible form body in PCAP and INetSim POST storage, hourly recurrence|Exfiltrates host telemetry using a web-form encoding format that resembles ordinary application submissions rather than structured JSON|
|**A04_4c**|HTTPS Base64 Blob Exfiltration|host identity → JSON serialization → Base64 encoding → HTTPS POST → controlled collection endpoint|`CryptBinaryToStringA`, `CRYPT_STRING_BASE64`, `CRYPT_STRING_NOCRLF`, `InternetOpenA`, `InternetConnectA`, `HttpOpenRequestA`, `INTERNET_FLAG_SECURE`, `InternetQueryOptionA`, `InternetSetOptionA`, `HttpSendRequestA`|`c2.lab.local`, `/api/v1/report`, `DataPipelineAgent/1.2`, `text/plain`, Base64 encoding constants, certificate-bypass flags, JSON field names, `location_heartbeat`|DNS query, TCP connection to port 443, TLS handshake, certificate exchange, encrypted application data, periodic HTTPS sessions; Base64 body visible through server-side POST capture but not ordinary PCAP inspection|Adds application-layer encoding and TLS transport protection, obscuring the original JSON both through Base64 representation and encrypted network transmission|
|**A04_4d**|Staging, Compression, and Authenticated SMB Exfiltration|host identity → JSON serialization → in-memory compression → local staging file → authenticated SMB share → remote archive|`CreateCompressor`, `Compress`, `CloseCompressor`, `COMPRESS_ALGORITHM_MSZIP`, `COMPRESS_RAW`, `CreateFileA`, `WriteFile`, `WNetAddConnection2A`, `WNetCancelConnection2A`, `CopyFileA`, `NETRESOURCEA`|`C:\Windows\Temp\stage.lz`, `\\c2.lab.local\sharestage`, `report.lz`, hardcoded SMB username and password, compression constants, UNC path strings, JSON field names|Creation and overwrite of `stage.lz`, DNS lookup for `c2.lab.local`, TCP port 445 connection, SMB negotiation and authentication, tree connection, remote file creation and write operations, Samba-side creation of `report.lz`|Stages collected telemetry as a compressed local artifact and transfers it through an explicitly authenticated SMB session, producing linked filesystem, authentication, and network evidence|
|**A04_5**|Integrated Spyware Collection and Staged Exfiltration|multiple collection sources → unified telemetry bundle → staging and optional compression → outbound transfer → cleanup or recurring collection|Expected mechanisms may combine keyboard capture, host reconnaissance, credential-related collection, file I/O, structured serialization, compression or archiving, timing logic, and one or more network transports such as HTTP, HTTPS, or SMB|Expected artifacts include multiple collection modules, shared aggregation structures, staging-directory paths, serialization and compression routines, C2 or share configuration, cleanup logic, periodic execution loops, and strings linking several A04 behaviors|Expected activity includes sustained spyware execution, keystroke or credential-related collection, host-enumeration processes or API calls, creation of aggregated staging files, optional archive generation, outbound network transfer, periodic callbacks, and cleanup of temporary artifacts|Integrates multiple spyware behaviors into a single end-to-end pipeline that collects heterogeneous host data, aggregates it, stages it, and simulates coordinated exfiltration|
